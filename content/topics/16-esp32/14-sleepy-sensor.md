## Цель

Проверим, как на самом деле работает deep sleep: соберём датчик, который раз в 10 минут просыпается на несколько секунд и отправляет данные, а потом измерим токи. Мы увидим, что DevKit в deep sleep потребляет миллиамперы, и научимся это исправлять. Это проект про честный расчёт и измерение.

## Что понадобится

- ESP32 DevKit (можно и голый модуль ESP32-WROOM с LDO HT7333 или аналогом).
- BME280, аккумулятор 18650 **с платой защиты** и держатель, модуль заряда TP4056 с защитой (из темы про Li-ion). Для измерений тока аккумулятор можно заменить лабораторным блоком питания WANPTEK TPS3010: 3,70 В, предел тока 0,3 А.
- Мультиметр Rigol DM858E с режимом мкА/мА или модуль INA219, осциллограф Rigol DHO804 и шунт 1 Ом для профиля тока.
- Паяльник, кусачки, пинцет (для удаления светодиода).

## Расчёт

- **Цикл:** T = 600 с: активность 3 с при 80 мА (Wi-Fi, отправка), сон 597 с при 10 мкА (идеальный чип).
- **Средний ток (идеал):** (80·3 + 0,01·597)/600 = **0,41 мА**.
- **Срок от 18650 (2600 мА·ч):** 2600/0,41 ≈ **6341 ч ≈ 264 суток**; с поправкой 0,7 ≈ 185 суток.
- **Если сон «обычного DevKit» 6 мА:** I_ср = (240 + 6·597)/600 = **6,37 мА**; срок 2600/6,37 ≈ 408 ч ≈ **17 суток**.
- **Вывод:** паразитные потребители платы сокращают срок в 15 раз.

## Сборка по шагам

1. Отключи питание. Собери схему: BME280 на I²C (GPIO21, GPIO22), питание 3,3 В.
2. Загрузи скетч deep sleep:

```cpp
#include <WiFi.h>
#include <esp_sleep.h>
#include <Wire.h>
#include <Adafruit_BME280.h>

RTC_DATA_ATTR int bootCount = 0;
Adafruit_BME280 bme;

void setup() {
  Serial.begin(115200);
  bootCount++;
  Wire.begin(21, 22);
  bme.begin(0x76);
  float t = bme.readTemperature();
  Serial.printf("Пробуждение %d, T = %.1f C\n", bootCount, t);

  // здесь можно подключиться к Wi-Fi и отправить значение (≈ 3 с)

  esp_sleep_enable_timer_wakeup(600ULL * 1000000ULL);   // 10 минут
  esp_deep_sleep_start();
}

void loop() {}
```

3. Подключи мультиметр (режим мкА/мА) последовательно с питанием 3,3 В или используй INA219 с записью.
4. Измерь ток во сне, затем в активной фазе. Запиши.
5. Убери светодиод питания (выпаяй или перережь дорожку), замени AMS1117 на малопотребляющий LDO — повтори измерение.
6. Рассчитай срок от 18650 по реальным значениям и сравни с расчётом.

|---|---|---|---|---|
| DevKit как есть | | | | |
| Без светодиода | | | | |
| Модуль + HT7333 | | | | |

## Проверка

Ожидай: DevKit как есть — 5–15 мА во сне (срок 10–30 суток); без светодиода — 3–8 мА; модуль с LDO — 20–100 мкА (срок 200+ суток). Активная фаза 80–150 мА. Если сон показывает 0,01 мА на DevKit — измерение сделано мимо стабилизатора или мультиметр на неверном пределе.

## Если не работает

- **ESP32 не просыпается.** Не задано пробуждение по таймеру или его значение в миллисекундах вместо микросекунд.
- **Ток сна больше ожидаемого.** Остались светодиод, стабилизатор и USB-мост; датчики питаются постоянно.
- **Мультиметр показывает 0 в активной фазе.** Предел мкА перегорел: используй предел мА и INA219 для импульсов.
- **Перезагрузка при активной фазе.** Пик тока просаживает питание: поставь конденсатор 100–470 мкФ.
- **Показания нестабильны.** Подключение щупов мультиметра создаёт падение напряжения (burden); измеряй INA219.

## Идеи развития

- Добавь отправку данных по MQTT перед сном и сравни время активной фазы с BLE-вариантом.
- Используй ULP-сопроцессор для измерений без пробуждения основного ядра.
- Добавь пробуждение по кнопке (EXT0) и режим «показать данные».
- Подключи солнечную батарею и оцени автономность.

```checkpoint

  - Ток измеряют мультиметром (мкА/мА) или INA219; импульсы активной фазы мультиметр усредняет.
```
